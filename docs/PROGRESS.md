## Deviations from the approved plan

- **pgvector locally is 0.8.6, not 0.8.1.** PostgreSQL's apt repository publishes no 0.8.1 package for PostgreSQL 18, and compiling it pulls in LLVM, which would add minutes to every CI run. PostGIS is 3.6.4 locally against 3.6.3 on RDS. Both are patch-level differences; re-check before vector features ship.
- **Some packages are one release behind the newest.** pnpm 11 won't install a version less than a day old (its minimum release age), so where the newest was that young, the one before it is pinned. Currently (checked 2026-09-11): zod 4.6.1 (newest 4.6.2), expo 57.0.21 (57.0.22), expo-router 57.0.20 (57.0.21), expo-linking 57.0.9 (57.0.10), expo-constants 57.0.17 (57.0.18), use-intl and next-intl 4.14.3 (4.14.4), and `@tanstack/react-router` 1.170.34 (1.170.35). Bump them once they qualify. (vite was held at 8.2.2 the same way, and is now 8.3.0.)
- **Three migrations instead of two.** Generated SQL (0001, the tables) is kept apart from hand-written SQL (0002, the append-only trigger and the policy seeds), so a regenerated migration never mixes with custom code.
- **No `attempts` or `last_error` columns on `outbox`.** Each handler runs as its own Graphile Worker job, which already records its attempts and last error (ADR-0015).
- **Claude Code file protection goes slightly beyond the plan.** Besides the hook and the two read denies, reads of `.env.*.local` are denied, and the protected patterns with no exceptions also get `Edit` deny rules, which catch shell redirections the hook can't see (ADR-0009, implementation notes).

## Environment notes

- The development machine runs Windows 11, with PowerShell and Git Bash. Git has `core.autocrlf=true`, so `.gitattributes` enforces LF line endings.
- pnpm 11.26.0 is installed for the user. Node is 24.20.0. Claude Code is 2.1.263.
- Docker Desktop must be running for `pnpm infra:up` and the integration tests. The first integration run builds the Postgres image (a minute or two); later runs take about 45 seconds.
- `ui-web`'s Vitest run is slow to start on this machine and sometimes times out before any test runs: jsdom takes about 50 seconds to set up, and twice now (2026-09-11, and again on 2026-09-12 with an empty Turbo cache) the run failed with "Failed to start forks worker" after 60 seconds. A rerun passes in seconds, with all 6 tests green. If a worker times out on a first run, run the tests again before investigating further; if it starts happening on Linux too, raise Vitest's `testTimeout` for that package rather than deleting the tests.
- The local Docker Compose stack publishes every port on `127.0.0.1` (the M0 security review). All five services are running and healthy on 2026-09-12; stop them with `pnpm infra:down`.
- The subagents and skills in `.claude/` load when a session starts, so a session that created them can't call them by name. The M0 reviews ran in a session started afterwards.
- Turbo runs the cached tasks (`build`, `lint`, `typecheck`, `test`) in strict environment mode, so only declared variables reach them. The apps' public variables need no declaration: Turbo's framework inference hashes and passes `NEXT_PUBLIC_*`, `VITE_*` and `EXPO_PUBLIC_*`. The telemetry opt-outs and `CI` pass through without changing cache keys. `pnpm dev` and `pnpm test:int` are never cached, so they run in loose mode and see the whole shell environment.
- On GitHub Actions, Turbo's `auto` log order groups each task's output and prints it only when the task finishes, so a persistent `dev` task's logs never appear. CI's first run on pull request #1 showed it: `verify` and `integration` passed, but the smoke job failed its last check. All six servers answered and `/v1/ready` reported ready, yet `dev.log` never received the worker's start line. `pnpm dev` and `pnpm dev:api` now pass `--log-order=stream`, which is already the default outside CI, and the smoke job gives the worker's line up to a minute to arrive.
- When an AI coding agent runs `next dev`, Next.js writes `apps/customer-web/AGENTS.md` and a `CLAUDE.md` that imports it, pointing agents at the Next.js docs bundled in `node_modules/next/dist/docs/`. There's no setting to turn this off, so both are committed unchanged.
- Claude Code loads the project settings (the hooks and deny rules) only when a session starts at the repository root.
- `docs/Short - UK Technology Quick-Commerce Marketplace Requirements.pdf` is untracked. It isn't committed until the founder decides what to do with it.
