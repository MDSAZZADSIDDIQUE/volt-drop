# @voltdrop/api-client

The typed client every VoltDrop app uses to call the API (spec §4). Fetch functions and TanStack Query v5 hooks are generated by orval from the API's OpenAPI 3.1 document.

## Use it

```ts
import { configureApiClient, ApiProblem, useGetHealth } from '@voltdrop/api-client';

configureApiClient({ baseUrl: import.meta.env.VITE_API_BASE_URL });
```

Then call the generated hooks, such as `useGetHealth()`, inside a `QueryClientProvider`. Function and hook names come from each route's operation id (ADR-0013). Every failed request throws an `ApiProblem`:

- branch on `problem.code` (for example `validation-failed`), which never changes;
- show `problem.message` (the problem's detail, or its title) to people;
- use `problem.fieldErrors` for form validation.

## Regenerate it

```bash
pnpm api:generate
```

This builds the API, writes `openapi.json` without starting a server, and runs orval. Commit both `openapi.json` and `src/generated/`. Regenerating an unchanged API gives identical files, so CI can fail on any difference; M0 step 9 adds that check.

## Don't edit

- `src/generated/` is replaced on every run. It isn't linted or formatted. M0 step 10 adds a Claude Code hook that blocks edits to it.
- `openapi.json` comes from the API's controllers and zod schemas. Change those instead.

Hand-written code lives in `src/fetcher.ts` (the transport) and `src/problem.ts` (errors).
